# State-to-Android integration map

[Specification index](../../REFERENCE_SPEC.md) · [iPhone capture definitions](../reference/02-state-capture.md) · [Android event contracts](../android/06-android-events.md) · [platform proof gates](08-platform-proof-gates.md)

This is a traceability map, **not** a parity result. Every row is `unverified` until its iPhone 18 Pro Max capture and paired target Android run satisfy the [acceptance record](09-implementation-acceptance.md). “SystemUI” means a change to a selected, buildable device OS; it is not a capability of an installable APK. “Publisher” means a specific Android app/version whose notification, media session or other documented contract has been inspected. The platform evidence and limits are cited in the linked architecture, event, permission and proof-gate files.

## Closure rule

For every row, record the selected Android model, OS build, source app and version (where applicable), granted access, actual event fields, available actions, rendering owner, iPhone capture ID, paired Android clip, and visual/functional verdict. Use `unsupported` for a demonstrated missing platform capability, `approximate` for a measured difference, and `unverified` while proof is absent. A row cannot become `matched` from a source citation, preview, or synthetic event alone.
