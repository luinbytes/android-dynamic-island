# Layout, interaction and Live Activity lifecycle

[Capture protocol and measurement sheet](02-state-capture.md) · [Specification index](../../REFERENCE_SPEC.md)

| ID | Trigger and state | What to measure | Current evidence |
| --- | --- | --- | --- |
| R0 | Idle, no activity, portrait | Sensor/black-mask rectangle, top offset, visible edge, status-bar relationship | **Measure** on iPhone 18 Pro Max |
| R1 | Start one Live Activity with valid assets/data; separately attempt the same start with an image larger than its target presentation and with combined static/dynamic data above 4 KB | For the accepted start: leading/trailing bounds, sensor gap, total width/height and content alignment. For each invalid attempt: encoded-data or image dimensions, request result/error, ActivityKit ID and active-state query, first Island frame or reproducible absence, then a corrected retry | Presentation confirmed; geometry **measure**. Apple says an oversized presentation image **might** prevent start and limits combined static/dynamic data to 4 KB. The published minimal-view 45 × 36.67 point image example is guidance, not an assumed iPhone 18 threshold; native acceptance/failure **measure**. [Apple ActivityKit constraints](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities) |
| R1a | Start an activity while its publisher app is foreground; leave for Home and another app, then tap the Island to return; repeat with activity already running when the app opens | Source-view-to-Island path, first visible frame, contour/content continuity, app-window motion, return destination and interruption by Home/recents gestures | Apple's design session shows one app-to-Island handoff; iPhone 18 trajectory and whether each publisher uses it **measure**. [WWDC23 design session](https://developer.apple.com/videos/play/wwdc2023/10194/) |
| R1b | Keep a fixture Live Activity active while its publisher app is foreground, leave to Home/another app and return; repeat with another app's Live Activity already present, then end the source in foreground | Active source versus visible Island IDs, whether the foreground publisher's card is shown/hidden/replaced, competing-source selection, first/last frame, tap target and task continuity | Apple says an app's Live Activity appears in the Island while the app is away and other items can appear while the app is open; exact target-phone foreground policy **measure**. [Foreground ownership](../android/21-foreground-ownership.md) |
| R2 | Touch and hold R1; expanded; swipe up to collapse | Start/finish silhouette, maximum width/height, content movement, release/collapse behavior | Gestures confirmed by [iOS 27 Island guide](https://support.apple.com/guide/iphone/view-live-activities-in-the-dynamic-island-iph28f50d10d/27/ios/27); geometry/timing **measure** |
| R2a | Expand activities with short, long, or prioritized leading/trailing content, including an explicit low-content and high-content variant | Center/leading/trailing/bottom regions, line breaks, content moved below the sensor, resulting pill height and height-change motion | ActivityKit documents content-dependent expanded placement; HIG recommends dynamic height; native examples **measure**. [Apple ActivityKit presentation guide](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities), [Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities) |
| R2b | In one controlled ActivityKit publisher, hold text, symbols and region priorities fixed while varying `contentMargins` for compact-leading, compact-trailing, minimal and expanded modes; then vary one expanded region's margins only | Content-to-sensor and content-to-contour gaps, clipping, line breaks, expanded region bounds, any outer-contour change, mode-switch motion and hit bounds | Apple documents per-mode and per-expanded-region margin overrides; exact default values and iPhone 18 response **measure**. [Apple custom Live Activity views](https://developer.apple.com/documentation/activitykit/creating-custom-views-for-live-activities), [expanded-region margins](https://developer.apple.com/documentation/widgetkit/dynamicislandexpandedregion/contentmargins%28_%3A_%3A%29) |
| R3 | Tap a single compact Live Activity and a Voice Memos recording; compare touch and hold | Whether tap expands, switches, opens the source app, or does nothing; source-specific hit region and transition | General Island guide documents hold-to-expand; Voice Memos guide describes tap-to-expand or return, so the tap result **measure** by source. [iOS 27 Island guide](https://support.apple.com/guide/iphone/view-live-activities-in-the-dynamic-island-iph28f50d10d/27/ios/27), [Voice Memos guide](https://support.apple.com/guide/iphone/make-a-recording-iph4d2a39a3b/27/ios/27) |
| R3a | Start two activities from one controllable app with distinct record IDs and `widgetURL` destinations, each with one shared leading/trailing destination; compare a no-URL variant, an expanded `Link` and an intent-backed button. Tap each leading/trailing/minimal/expanded region, then repeat after reorder, app process restart and lock | Exact scene/record opened, URL or `NSUserActivityTypeLiveActivity`, selected-source identity, whether the button acts in place, launch/unlock path and canceled/wrong-route behavior | Apple documents default user-activity launch, deep links and shared compact leading/trailing destination; their source-specific hit and handoff behavior on the target phone **measure**. [Apple launch contract](https://developer.apple.com/documentation/ActivityKit/launching-your-app-from-a-live-activity) |
| R4 | Two simultaneous activities; tap to select; repeat with short and long minimal content in each source | Which minimal activity attaches, detached circle versus oval contour and content threshold, gap, ordering, selection and tap result | Apple HIG confirms two minimal presentations, one attached and one detached, with content-dependent circular/oval detached shape; exact threshold and native geometry **measure**. [Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities) |
| R5 | Three simultaneous activities from controlled publishers whose compact-leading, compact-trailing and minimal views have **distinct marker content**; swipe across and vary each minimal-content width | Which published view appears in each of the three visible positions, each side shape/gap, whether either is attached, ordering, selection, swipe direction/result, expansion and order after updates | Apple's general HIG illustrates two minimal activities while the iPhone 18 Pro guide allows three visible; the third item's publisher-view choice and layout are **not** specified by that older illustration. Apple launch demo shows small-left + long-center + small-right; native view identity, dimensions and cross-app priority **measure**. [Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities), [iOS 27 Island guide](https://support.apple.com/guide/iphone/view-live-activities-in-the-dynamic-island-iph28f50d10d/27/ios/27) |
| R5a | Attempt two and three Live Activities from one controllable app with equal and unequal `relevanceScore`; change scores, end the winner, then add activities from a second and third app | Start-limit errors, number visible from each publisher, compact/minimal/three-slot presentation, tie order, promotion after score update/end and whether user selection survives reprioritization | Apple documents highest-score and earliest-start tie rules **within one app**, plus one compact presentation when no other app publishes; cross-app iPhone 18 arbitration **measure**. [ActivityKit relevance score](https://developer.apple.com/documentation/activitykit/activitycontent/relevancescore), [presentation guidance](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities) |
| R5b | Keep four or more confirmed active activities from separate fixture publishers; start the fourth while three are visible, then update and end each visible and nonvisible source in different orders | Whether all requests remain active, which three appear, hidden-source access through swipe or other route, slot/order changes, selected-item persistence and promotion after a visible source ends; record whether a nonvisible source still appears on Lock Screen | Apple's iOS 27 guide confirms **up to three visible** Island activities, not the overflow selection or promotion algorithm; native behavior **measure**. [iPhone Island guide](https://support.apple.com/guide/iphone/view-live-activities-in-the-dynamic-island-iph28f50d10d/27/ios/27) |
| R5c | Keep one ActivityKit ID while its publisher rotates through scored point, substitution and foul event payloads; repeat with a second publisher activity and compare two truly separate activities | Stable source/slot/selection identity, per-event content and action destination, skipped/coalesced updates, contour and element motion, timing and tap result | Apple recommends one dynamic Live Activity for multiple events; exact iPhone 18 transitions and publisher cadence **measure**. [One-activity rotation](../features/30-one-activity-rotating-content.md) |
| R5d | With one, two and three active activities, try inward/outward and cross-Island swipes on each visible shape and gap; after any apparent hide, update, alert, lock/unlock, restore and end the source in separate trials | Whether iOS 27 supports hide/restore, exact gesture versus activity switching, visible/selected IDs, source lifecycle and Lock Screen state, restoration trigger and input conflict with Search/Siri | A 2024 Apple Support video describes hiding/opening activities, while the iOS 27 guide documents cross-Island navigation; target-build result **measure**. [Hide/restore contract](../features/37-activity-hide-restore.md) |
| R6 | Alerting Live Activity update while unlocked and locked; distinguish iPhone Island alert from the documented banner on devices without an Island | Temporary expansion, duration, screen wake, sound, priority over other activities, Focus/mute behavior, any separate notification/Lock Screen presentation and return state | Apple HIG documents expanded Island alert, screen light and default notification sound. ActivityKit's unlocked Home Screen banner example is for phones **without** an Island; iPhone 18 timing and coexistence **measure**. [Apple ActivityKit presentation guide](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities) |
| R6a | Ordinary nonalerting content update to the same activity; separately attempt a combined static/dynamic payload above 4 KB, then send a valid update | Text/number replacement, shape change, animation and whether screen/sound remain quiet. For the oversized-data attempt: encoded bytes, update result/error, current ActivityKit state, Island frame/absence and whether the subsequent valid revision is accepted | ActivityKit distinguishes updates with and without alert configuration and caps combined static/dynamic data at 4 KB; exact iPhone response to an oversized update **measure**. [Apple ActivityKit constraints](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities) |
| R6b | Update one text field, one image/SF Symbol, one numeric value and a multi-element layout in controllable third-party activities. Repeat identical payloads with default animation, `contentTransition`, `animation(_:value:)` using two distinct timing curves, and animation disabled; repeat during a second update and Always-On dimming | Per-element blur, opacity, scale and position paths; element identity, unchanged-field stability, contour motion, overlap, duration, whether the declared timing changes the observed curve, and whether disabled animation actually suppresses it | Apple's current WidgetKit guide limits the modifier-ignored rule to iOS 16 or earlier, while a separate ActivityKit guide states it broadly; iOS 27 modifier effect and actual iPhone 18 curves **measure**. [WidgetKit animation guide](https://developer.apple.com/documentation/widgetkit/animating-data-updates-in-widgets-and-live-activities) |
| R7 | End/remove each activity | Exit motion and next-activity promotion | **Measure** |
| R8 | Repeat R0–R7 in landscape. In a controlled publisher, vary compact-leading, compact-trailing and minimal text/content with and without an alternate view selected by `isDynamicIslandLimitedInWidth`; separately expand the same activity | Per-mode width flag and switch threshold, substitution versus truncation, expanded reflow, sensor-relative location, gestures and transitions | Apple applies the limited-width environment to compact-leading, compact-trailing and minimal, and WWDC26 shows a landscape compact-trailing substitution; actual iPhone 18 thresholds and expanded layout **measure**. [Apple limited-width API](https://developer.apple.com/documentation/swiftui/environmentvalues/isdynamicislandlimitedinwidth) |
