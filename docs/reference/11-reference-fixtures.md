# Reproducible reference fixtures

[Specification index](../../REFERENCE_SPEC.md) · [capture matrix](02-state-capture.md) · [state-to-Android map](../verification/10-state-to-android-map.md)

The capture cases cannot be closed with screenshots from unrelated apps. Build small, **ordinary** publisher apps only to trigger controllable ActivityKit and Android publisher states. Keep the fixtures separate from the replica renderer and log the exact fixture version, build, trigger ID and source state with each capture. A fixture proves what its own publisher emits; it does not prove how every third-party app behaves. No fixture should imitate a system-authentication success, privacy indicator, **cellular call**, AirDrop, Siri, screen recording or flashlight event. R10m instead needs an actual consented test VoIP conversation reported through each platform's communication framework.

## iPhone ActivityKit publisher

Build a signed test app and widget extension against the selected iOS 27 SDK when an Apple build environment and reference iPhone are available. Use real `ActivityKit` requests/updates/ends and `WidgetKit` Dynamic Island regions; drive them from an on-device control screen so each event has a visible trigger time. Apple documents these APIs and the four presentations in [ActivityKit guidance](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities). Avoid relying on simulator screenshots as iPhone 18 Pro Max pixel or timing evidence.

## Android publisher fixture

Use a **different package** from the replica so notification-listener and cross-app media behavior is genuine. On the chosen Android version, publish uniquely identified notifications and an active `MediaSession`, with a visible control screen and source-state log. Exercise ordinary and ongoing notifications; qualifying `ProgressStyle`/Live Update requests only for an actually running user-initiated test task. Promotion is system-decided, so record `FLAG_PROMOTED_ONGOING` from the listener rather than assuming the request succeeded. [Android notification listener](https://developer.android.com/reference/android/service/notification/NotificationListenerService), [Live Update rules](https://developer.android.com/develop/ui/views/notifications/live-update), [MediaSessionManager](https://developer.android.com/reference/android/media/session/MediaSessionManager).

Log native mic indicator, foreground-service lifetime and replica teardown without inferring channel state from mic-use alone. [PTT contract](../features/34-push-to-talk-channel.md) |

Real third-party apps still require a per-publisher/version acceptance run. The fixture establishes adapter mechanics; it cannot establish that another timer, navigation, delivery, recorder or transfer app publishes equivalent data.

## Capture run record

For each run, keep: `R` ID, fixture commit/build ID, source app/package, OS build, permissions/settings, exact trigger and monotonic event timestamp, source activity/notification/session key, before/after fields, native screen clip, external camera clip, and resulting action. Use nonpersonal sample content. Synchronize the footage with a visible trigger marker; keep screen-recording indicators in the capture context rather than silently cropping them out. Store failed or absent presentations as results too. Apply the [measurement sheet](02-state-capture.md) and [acceptance record](../verification/09-implementation-acceptance.md) before assigning a parity verdict.
