# App Clip Live Activity start

[Specification index](../../REFERENCE_SPEC.md) · [capture matrix](../reference/02-state-capture.md) · [destination routing](../android/19-destination-routing.md)

Apple permits an App Clip to bundle a **Live Activities-only** widget extension and start an ActivityKit activity visible in the Dynamic Island without the full app installed. The extension needs the App Clip capability and its bundle identifier must be prefixed by the App Clip identifier. This establishes a distinct **publisher installation and invocation path**, not a new Island geometry rule. Apple's documentation does not specify what an iPhone 18 Pro Max on iOS 27 does to an active App Clip activity when the full app is later installed or the clip is removed; capture that behavior. [Apple App Clip Live Activities](https://developer.apple.com/documentation/appclip/offering-live-activities-with-your-app-clip), [App Clip invocation](https://developer.apple.com/documentation/appclip/configuring-the-launch-experience-of-your-app-clip).

## R22d reference capture

Use a controlled App Clip and a separate full app build from the same developer. On a clean reference phone with the full app absent, invoke the clip from a test App Clip Code or supported link and start one identified Live Activity. Log invocation URL, clip/full-app installation state, clip process state, ActivityKit ID, first Island frame, tap destination, update and end. Repeat with another activity visible and while locked. Then install the full app during a separate active clip activity and test update, tap, expanded action, end and source identity; remove the clip in a separate trial. Record any failure or transition without assuming the activity transfers to the full app. Avoid treating the App Clip card, an ordinary notification or full-app install prompt as Island content.

Measure the same contour, content, timing and gestures as R1–R7, but keep the **invocation/install boundary** in the evidence record. The parity question is whether the user can begin and control the task from a no-full-app entry path, not whether two otherwise identical pills have different pixels.

## Android route and capability boundary

Google states that Play stopped serving Google Play Instant apps in December 2025. It recommends regular installed apps with deep links. A verified Android App Link can take a URL to the corresponding content **when the app is installed**; the link itself does not publish an ongoing task or notification. Therefore the current public Play path cannot be assumed to reproduce Apple's no-full-app App Clip start. For an app-owned Android fixture, use an installed publisher reached through a verified App Link, create a real task, and publish its own ongoing notification or eligible Live Update. A separate web page can begin a server task but cannot give the replica third-party notification fields or commands until an installed cooperating publisher exposes them. Label this route `approximate` if the iPhone no-install start succeeds and the Android path requires installation; keep any selected OEM or store-specific alternative unverified until demonstrated. [Play Instant retirement](https://developer.android.com/topic/google-play-instant/overview), [Android App Links](https://developer.android.com/training/app-links/about), [Android Live Updates](https://developer.android.com/develop/ui/views/notifications/live-update).

On the selected Android build, test link verification, installed/uninstalled outcomes, publisher task ID, notification key, promotion flag, exact record reached by tapping the replica and native chip, app installation/update during a live task, and teardown. A notification listener must not invent an active task from a web URL or merge a newly installed package with an older source by title alone. Keep source, installation, notification and destination identities separate.

**Verdict:** iOS 27 appearance and transfer behavior `unverified` until R22d native captures; Android no-install capability `unsupported` for the retired Play Instant route, with any installed-app or target-specific route scored after device proof. No 1:1 verdict is available now.
