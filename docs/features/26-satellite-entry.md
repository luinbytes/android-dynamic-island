## Documented iPhone path and limits

Apple's roadside-assistance instructions say that, while off-grid, Messages can show a **Use Messages via Satellite** prompt and that tapping the prompt, then tapping the Dynamic Island again, opens Connection Assistant. Apple's Messages via satellite guide separately documents **connection-strength dots** in the Island and, when the connection could improve, arrows directing a left or right turn; tapping the Island opens Connection Assistant. This establishes an ongoing guidance presentation, but neither guide specifies the iPhone 18 Pro Max contour, dot count/scale, arrow animation, update cadence or behavior across every satellite service. Satellite availability depends on region, device and service conditions. With cellular or Wi-Fi, Control Center's Satellite option opens a demo, which is a separate path and must not be scored as a real Island connection. [Apple roadside-assistance steps](https://support.apple.com/en-us/105098), [Apple Messages via satellite](https://support.apple.com/en-us/120930).

Apple's [illustrative Messages satellite image](https://cdsassets.apple.com/live/7WUAS350/images/ios/ios-26-iphone-16-pro-messages-connected-via-satellite-off-grid.png) shows a large black guidance region around the sensors over a Messages conversation, with a “Keep Pointing at Satellite” instruction, a Connected status and a bright connection symbol. Its asset identifies **iOS 26/iPhone 16 Pro**. It is evidence of one published composition, not the iPhone 18 Pro Max/iOS 27 contour, the compact-dot state, an expansion gesture or the transition between them. Record text, symbol, horizon/background treatment, black-region bounds and Messages content displacement on the target phone before using this image for Android layout decisions. [Apple Messages via satellite](https://support.apple.com/en-us/120930).

The iOS 27 status-icon guide describes a **Satellite features** icon as showing that Emergency SOS, Find My, Roadside Assistance and Messages via satellite are available in the location; it separately describes **SAT** as carrier-provided satellite use. Neither status meaning alone identifies an active Messages connection or proves that its Island strength dots/arrows are visible. Keep service availability, carrier service use, Connection Assistant guidance and actual Messages traffic as separate observations. Apple's published dot/arrow description is explicitly in the Messages-via-satellite path; do not copy it into an Emergency SOS, Find My or roadside UI claim without its own source or native capture. [iOS 27 status icons](https://support.apple.com/guide/iphone/learn-the-meaning-of-iphone-status-icons-iphef7bb57dc/27/ios/27), [Apple Messages via satellite](https://support.apple.com/en-us/120930).

Capture R27 only with an eligible reference phone and service region. Use the safe Connection Demo first to learn the guidance UI, labeling all demo footage. For the documented Island route, capture the actual Messages prompt and each tap on an eligible off-grid connection, recording the visible Island state before and after, Connection Assistant destination, pointing instructions, connection progress, return path, lock behavior and coexistence with another activity. Do not initiate an emergency call or assistance request as a visual fixture. If real off-grid conditions are unavailable, keep the route `unverified`; a demo cannot close it.

For R27a, keep the same real Messages satellite session running and externally film the Island through a strong connection, degraded connection if naturally observable, a left/right pointing instruction when offered, tap to Connection Assistant, return, connection loss and end. Capture both any compact dots and any larger guidance presentation; determine whether the latter is automatic, transient or gesture-driven, and how it moves Messages content. Log the visible signal/pointing state beside each frame, plus the Messages send/receive phase and any separate Satellite features or carrier SAT status icon; a delayed message or status icon is not proof of a particular dot count. Do not create a degraded satellite link or emergency interaction merely to fill a visual fixture. If conditions do not yield an arrow or connection loss, leave those variants `unverified`, not absent. The safe demo may inform layout exploration but cannot close real-connection parity. [Apple Messages via satellite](https://support.apple.com/en-us/120930).

## Android integration boundary

Android API 36's `SatelliteManager` exists only on devices advertising `FEATURE_TELEPHONY_SATELLITE`. Its public `registerStateChangeListener()` can report **satellite modem enabled state** with `READ_BASIC_PHONE_STATE`, `READ_PHONE_STATE`, privileged phone-state access or carrier privileges. That callback does not assert a live connection or provide strength dots, left/right pointing, an emergency/roadside session, Messages prompt or authority to open the selected OEM's satellite UI. An ordinary APK should therefore leave the system's satellite and emergency controls with their actual owner. On a selected build, inspect the telephony/OEM/SystemUI path and any documented destination before proposing an Island shortcut; a cooperating publisher may expose a specific notification/action or signal contract, but that must be verified by source and version. [SatelliteManager](https://developer.android.com/reference/android/telephony/satellite/SatelliteManager), [state callback](https://developer.android.com/reference/android/telephony/satellite/SatelliteStateChangeListener), [AOSP satellite overview](https://source.android.com/docs/core/connect/satellite).

For target-phone proof, record the feature flag, OS/build, satellite carrier/service availability, enabled callback value, native status/UI owner, actual connection/pointing signal owner and whether any verified action opens the same task. Compare R27 entry destination separately from R27a ongoing guidance geometry, state changes and tap result. `unavailable to ordinary APK` applies to a universal cross-app satellite session adapter on the documented callback; the selected SystemUI/OEM path remains `unverified` until inspected.
