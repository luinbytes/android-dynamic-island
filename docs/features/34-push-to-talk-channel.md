# Push to Talk channel indicator and controls

[Specification index](../../REFERENCE_SPEC.md) · [capture matrix](../reference/02-state-capture.md) · [Android event adapters](../android/06-android-events.md)

Apple's Push to Talk framework supplies system UI for joining a channel, holding a Talk control, receiving audio and leaving. Its channel descriptor supplies a name and image to the system UI; the system owns audio-session activation and microphone on/off chimes. Apple's older WWDC demonstration showed a blue status-bar pill, and an Apple engineer later described a joined channel indicator in the **status bar or Dynamic Island**. Neither source fixes the iPhone 18 Pro Max/iOS 27 location, shape or priority. Record a positive or negative current-device Island result; do not convert a prior blue-pill example into an iOS 27 design token. [Apple Push to Talk guide](https://developer.apple.com/documentation/pushtotalk/creating-a-push-to-talk-app/), [WWDC22 demonstration](https://developer.apple.com/videos/play/wwdc2022/10117/), [Apple engineer answer](https://developer.apple.com/forums/thread/780822).

## R10l native capture

Use a controlled Push to Talk app and test server with nonpersonal audio. Join one channel explicitly from the foreground, leave its app, tap the system indicator, hold/release Talk, receive a remote speaker event, switch to listen-only mode if supported, lose network, reconnect and leave. Repeat during a cellular call, while another Live Activity is compact or expanded, on Lock Screen, after system termination/relaunch and after device reboot. Log channel UUID, join/leave result, service status, speaker identity as supplied to the system, transmission callbacks, audio-session activation, APNs arrival and each visible Island/status-bar frame. The framework permits only one active channel system-wide, so a second-channel join attempt is an explicit failure case. [Apple Push to Talk guide](https://developer.apple.com/documentation/pushtotalk/creating-a-push-to-talk-app/).

Measure indicator location, blue tint if present, contour, channel name/image, tap destination, Talk hold threshold, activation chime, microphone/privacy indicator clearance, incoming-speaker changes, lock-screen controls, interruption priority and exit. Separate a **joined idle channel**, **transmitting**, **receiving**, **service connecting**, **failed transmission** and **left channel**. A generic phone-call card or orange mic dot cannot stand in for these phases.

## Android integration boundary

Android has no universal public Push to Talk channel feed established by the inspected notification and media-session APIs. For an app-owned communications publisher, keep its channel/session ID, joined state, transmit/receive phase, current speaker, command result and service status in an explicit contract. If it captures audio in a foreground service, follow the `microphone` service type, `RECORD_AUDIO` and while-in-use/background-start restrictions; Android owns the privacy indicator. A VoIP call integrated through Telecom is a separate call contract, not proof of a walkie-talkie channel. [Android microphone service type](https://developer.android.com/develop/background-work/services/fgs/service-types), [foreground-service background restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), [Core Telecom](https://developer.android.com/develop/connectivity/telecom/voip-app/telecom).

For another publisher, an enabled notification listener can observe only the notification fields and actions that publisher posts. A media session, mic-use dot, call state or notification text alone does not identify channel membership, current speaker, press-to-talk authority or a valid transmit command. Name the publisher/version and test its actual action token before showing controls. A selected SystemUI route must preserve telecom, keyguard, privacy-indicator and status-bar ownership, and it still needs a real publisher contract. [Android notification listener](https://developer.android.com/reference/android/service/notification/NotificationListenerService), [AOSP privacy indicators](https://source.android.com/docs/core/permissions/privacy-indicators).

**Parity verdict:** `unverified` until iPhone 18 Pro Max/iOS 27 and selected Android captures show the actual indicator and real channel behavior. A genuine app-owned channel is a direct data candidate; cross-app PTT semantics are publisher-dependent, while status-bar and lock surfaces are system-owned.
