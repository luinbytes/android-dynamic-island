# Live Voicemail Island handoff

[Specification index](../../REFERENCE_SPEC.md) · [R10s capture](../reference/02b-system-activities-capture.md) · [call route](../verification/10-state-to-android-map.md)

Apple's iOS 17 developer release notes explicitly refer to tapping a **Live Voicemail icon in the status bar or Dynamic Island** to open its transcript. The iOS 27 Phone guide still documents real-time transcription while a caller leaves voicemail, with **Accept** to pick up and **Stop** to end the incoming voicemail. It does not specify the iPhone 18 Pro Max Island geometry, whether the transcript is ever rendered *inside* the Island, or what changes when the current call-screening path runs first. The target capture must establish those details and distinguish the Island entry from the Phone call screen. Live Voicemail availability depends on carrier, language and region. [Apple developer release notes](https://developer.apple.com/documentation/ios-ipados-release-notes/ios-ipados-17-release-notes), [iOS 27 voicemail guide](https://support.apple.com/guide/iphone/set-up-voicemail-iph3c99490e/27/ios/27).

## R10s native capture

With a consenting test caller and a supported carrier/region, enable Live Voicemail. Record the device/build, Phone and FaceTime settings, caller category, Silence Unknown Callers, Focus, screening settings and transcript language. Let a cellular call go to Live Voicemail; repeat with an unknown caller, with a FaceTime audio call if supported, and with Live Voicemail disabled. Film from ringing through transcription, then separately (a) tap the status/Island icon, (b) accept while a message is being left, (c) stop without answering, and (d) let the caller finish. Run once with another activity visible and once with the phone locked. Record which surface owns every phase, icon location and shape, any expanded Island content, tap destination, transcript redaction, call/privacy indicators, audio behavior, action result and teardown timing. Use test speech; keep the recording and transcript private. A past iOS 17 icon path is evidence to **probe**, not proof of its iOS 27 placement.

## Android ownership

The selected Android phone's default dialer and Telecom path own live call UI and acceptance. `CallScreeningService` is a **user-selected role** that can screen before ringing; it does not itself expose another dialer's live voicemail transcript. `VisualVoicemailService` is bound only to the default dialer for carrier voicemail events and likewise does not establish an in-progress transcription feed for an overlay. Google Phone's Call Screen can display a real-time screening transcript on supported Pixels, but this is a different workflow from an unanswered call entering Live Voicemail. Inspect the actual dialer, carrier and OS behavior, notification fields/actions, current call status indicator and keyguard before specifying a replica cue. Do not request or replace a dialer/screening role solely to obtain a decorative Island state. [Android CallScreeningService](https://developer.android.com/reference/android/telecom/CallScreeningService), [Android VisualVoicemailService](https://developer.android.com/reference/android/telephony/VisualVoicemailService), [Google Phone Call Screen](https://support.google.com/phoneapp/answer/9094888).

R10s remains `unverified` for current iOS Island presence, appearance, actions and paired Android parity until the [comparison protocol](../verification/12-comparison-protocol.md) has native evidence. If Android lacks a real equivalent live voicemail source, record the functional layer as `unsupported` rather than animating a false transcript or pick-up control.
