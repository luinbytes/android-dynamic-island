# Action button start of a Live Activity

[Specification index](../../REFERENCE_SPEC.md) · [R22c capture](../reference/02-state-capture.md) · [Control Center start](../verification/10-state-to-android-map.md)

Apple's Live Activities design guidance recommends an App Shortcut that starts a Live Activity and explicitly gives assigning that shortcut to the iPhone Action button as an example. Apple's Shortcuts guide describes configuring the Action button to run a shortcut. These sources establish a **user-configured start path**, not the resulting iPhone 18 Island animation, behavior while locked, or whether a particular publisher implements it. Keep this path separate from an in-place Live Activity button, a Control Center `LiveActivityIntent`, a scheduled start and an APNs push-to-start. [Apple Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities), [Action button shortcuts](https://support.apple.com/en-gb/guide/shortcuts/apdfea15680b/ios).

An assigned **control** may also show its symbol and value in the Island during an Action-button hold without starting a Live Activity. Its transient feedback is a separate [R10j capture](32-action-button-control-feedback.md); this page covers the R22c task-start path. [Apple Controls HIG](https://developer.apple.com/design/human-interface-guidelines/controls).

## R22c native capture

Create an App Shortcut in a controlled publisher that requests one identified Live Activity, assign it to the Action button, and log shortcut execution and ActivityKit state. Press the button with the publisher foreground, with another app foreground, while locked, with three visible activities, when Live Activities are disabled for the publisher, and again while its task already exists. Record button press and haptic timing, first Island frame, compact/minimal/expanded result, wake/alert behavior, whether publisher UI opens, duplicate-start result, source ID, tap destination and return state. Repeat an unassigned button press as a negative control. Apple documents the start affordance, not a universal visible response; each presentation result must be measured on iOS 27.

## Android integration boundary

Android `ShortcutManager` can publish an app-owned task shortcut, including dynamic or pinned shortcuts supported by the selected launcher. The publisher must own the command and create the real task/notification; the replica then observes that task through its explicit integration or listener. A shortcut request is not proof that the user pinned it or that execution succeeded. This public shortcut API does not itself assign a physical hardware button or let the replica intercept another app's button. A hardware-button path requires the selected Android device's documented user/OEM mapping and a separate input-owner audit; do not promise a portable Action-button analogue. [Android ShortcutManager](https://developer.android.com/reference/android/content/pm/ShortcutManager), [Android app shortcuts](https://developer.android.com/develop/ui/compose/system/shortcuts/creating-shortcuts).

For target proof, record launcher and OS build, shortcut ID and user placement, actual invocation, task ID, notification/listener arrival, source action result, native chip, replica entrance and duplicate handling. Score **task start**, **button/shortcut affordance**, and **Island presentation** separately. A launcher shortcut can provide a real app-owned start without matching iPhone hardware input; a selected OEM button remains `unverified` until observed. [Notification admission](../android/20-notification-admission.md), [destination routing](../android/19-destination-routing.md).
