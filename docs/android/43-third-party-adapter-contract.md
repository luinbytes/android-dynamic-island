# Third-party publisher adapter contract

[Specification index](../../REFERENCE_SPEC.md) · [event adapters](06-android-events.md) · [notification admission](20-notification-admission.md) · [listener visibility](27-notification-listener-visibility.md)

A third-party Island source is admitted only after an adapter proves a **current task instance**, its available content, and every displayed action from that publisher's delivered Android contract. A notification listener reports notification records; it does not provide another app's private task model. `StatusBarNotification.getKey()` identifies a notification record, `getUser()` identifies its Android user, and `getOpPkg()` can differ from `getPackageName()` when a notification delegate posts for the owning app. Store those fields separately; package name or similar text alone is not a task ID. [Android StatusBarNotification](https://developer.android.com/reference/android/service/notification/StatusBarNotification).

## Adapter record

Each supported publisher/version gets a reviewable record with: package and observed `getOpPkg`; version/build range and OS/API range tested; user/profile scope; listener filter and permission prerequisites; notification or media-session admission predicate; task ID derivation; fields actually delivered; publisher `visibility`, optional `publicVersion` and current ranking lock-screen override; action token/transport owner and lock authentication behavior; current `FLAG_AUTO_CANCEL` and explicit-view handling for notification taps; freshness/end rule, including notification-removal reason versus confirmed task end; native chip/shade/lock coexistence policy; negative cases; and paired evidence IDs. A ranking override is an input, not a substitute for the selected build's effective privacy rendering. Unknown or changed fields fail closed for that field or action, while the native Android notification/media controls remain available. `PackageInfo.getLongVersionCode()` and `signingInfo` can help detect an updated or different installed publisher, but neither establishes the meaning of its notification fields without runtime inspection. [PackageInfo](https://developer.android.com/reference/android/content/pm/PackageInfo), [ranking visibility override](https://developer.android.com/reference/android/service/notification/NotificationListenerService.Ranking#getLockscreenVisibilityOverride()), [notification actions](https://developer.android.com/reference/android/app/Notification.Action), [listener click semantics](https://developer.android.com/reference/android/service/notification/NotificationListenerService).

Use `(UserHandle, notification key)` for a notification record and the actual `MediaSession.Token` for a media session. Keep a separate publisher task ID only when the publisher exposes one or a controlled fixture proves a stable mapping through updates. A `Notification.MediaStyle` can carry `EXTRA_MEDIA_SESSION`; when that token matches the controller's token, one source can reconcile its notification, media session and system chip. When the token is absent or differs, do not merge by package, title, artwork or post time. Keep the records distinct internally and admit only the positively identified media source to the Island unless a named adapter proves another task. Multiple sessions from one package and notification delegation are explicit negative fixtures. [Media notification token](https://developer.android.com/reference/android/app/Notification#EXTRA_MEDIA_SESSION), [MediaController token](https://developer.android.com/reference/android/media/session/MediaController#getSessionToken()), [notification owner and delegate](https://developer.android.com/reference/android/service/notification/StatusBarNotification#getOpPkg()).

For ordinary actions, bind the actual delivered `Notification.Action.actionIntent` or a controller transport command to that exact current source and action revision. Check whether an action exists and whether `isAuthenticationRequired()` requests unlock; a label or semantic hint does not create a command. After sending an action, wait for a publisher notification/session update or explicit app-owned acknowledgment before displaying success. If the notification is removed, the session closes, access is revoked, the profile locks or the publisher version changes, invalidate affected actions immediately and resnapshot before readmission. [Notification.Action](https://developer.android.com/reference/android/app/Notification.Action), [listener lifecycle](https://developer.android.com/reference/android/service/notification/NotificationListenerService), [MediaController](https://developer.android.com/reference/android/media/session/MediaController).

On API 37+, `MediaSessionManager` offers package-specific active-session retrieval/listening with the same privileged-or-enabled-listener gate for another package. This can reduce irrelevant callbacks; it does not replace token identity or grant private publisher task data. Earlier builds use the available active-session listener and filter records after retrieval. Record which API path the selected build actually supports. [MediaSessionManager](https://developer.android.com/reference/android/media/session/MediaSessionManager).

## Acceptance cases

1. One publisher posts a media notification tied to its active session token. Confirm one source ID and one Island card through play, pause, metadata update, native chip change and notification repost under the same key.
2. The same package owns two active sessions, or posts a notification with no token or a different token. Confirm no package/title-based merge and no control sent to the wrong controller.
3. A delegated notification has distinct owning and posting packages. Confirm the adapter's owner/version check, user/profile isolation, source identity and destination do not switch to the delegate by accident.
4. Revoke listener access, filter the ongoing type, lock a managed profile, update the publisher version, remove a notification and end a media session in separate trials. For removal, distinguish click, user dismiss, app cancel/repost, snooze, timeout, channel disablement and lockdown by actual callback reason. Confirm which source remains independently observed and that stale text/actions disappear without falsely canceling or reviving the publisher's task.
5. Deliver a same-package ordinary alert, a group summary and a promoted Live Update alongside the real task. Confirm admission uses the inspected task identity, preserves the native notification/chip, and does not create duplicate Island slots or promote unrelated content.
6. For a current notification with and without `FLAG_AUTO_CANCEL`, compare passive card display, explicit expansion, content tap and a separate action button. Record whether the listener marked a key viewed, called cancellation for an auto-cancel content tap, received removal, and preserved any independently confirmed source. Compare native shade seen/dismissal state before and after each path; do not make incidental drawing mutate either state. [Android listener seen/click API](https://developer.android.com/reference/android/service/notification/NotificationListenerService).

Record the exact delivered fields, user/profile, notification key, `getPackageName`/`getOpPkg`, session token presence and equality result, source ID, action owner/result, native surfaces and replica frames. A missing third-party field is `unsupported` for that adapter capability or `unverified` until the publisher/build is inspected; it is not permission to synthesize an iOS state. This contract defines the Android source boundary, while visual parity still requires the selected iPhone and Android captures.
