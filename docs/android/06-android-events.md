# Android event adapters

[Specification index](../../REFERENCE_SPEC.md)

## Android behavior mapping

### Meaning of full Android integration

The component should react to **real Android events**, show the current source app and state, invoke only actions that source actually exposes, and withdraw a card when its source ends or access is revoked. It should work over ordinary apps without requiring an iOS-style demonstration mode. An ordinary APK has the public-API boundaries below; a SystemUI implementation needs its own signal and permission audit on the selected OS and still depends on what third-party publishers expose. Avoid Accessibility scraping or display capture as a substitute for a missing event API. Those techniques would add broad access and still leave state and controls unreliable.

Use four labels in the product and acceptance record: **direct** (public state/control API), **publisher-dependent** (another app must publish a media session or usable notification), **role-dependent** (requires changing the app's system role), and **unavailable** (no ordinary third-party contract found). Never render a control that cannot perform its named action. Any adapter that has lost permission or a live source must immediately lose its “active” status; retain a brief exit animation only as presentation.

[Android playback info](https://developer.android.com/reference/android/media/session/MediaController.PlaybackInfo), [remote media contract](../features/38-remote-now-playing.md) | **Publisher-dependent cross-app; direct for a cooperating publisher.** Test delayed updates, disconnect and action failures. |

[Battery intent](https://developer.android.com/reference/android/content/Intent#ACTION_BATTERY_CHANGED) | **Direct.** |
| Ringer/vibrate/silent | Query `AudioManager.getRingerMode()` and observe `RINGER_MODE_CHANGED_ACTION`. If an app-owned control offers a change, invoke it through its actual owner and re-read the state before reporting success. | Public ringer **observation** does not prove Do Not Disturb, a hardware switch or permission to change ringer mode. Android 17 can silently ignore `setRingerMode()` from an app without a visible Activity or qualifying foreground-service state; API 37 targets have an additional while-in-use service gate. Do not infer success from a return without error. [AudioManager](https://developer.android.com/reference/android/media/AudioManager), [Android 17 background audio](https://developer.android.com/about/versions/17/changes/bg-audio) | **Direct for ringer state; control conditional on real lifecycle and post-action result.** Verify R10h/R10j when offering a toggle. |
| Flashlight | `CameraManager.registerTorchCallback()` gives current and future torch state; `setTorchMode()` can control a supported flash unit, subject to camera availability. | These torch methods do not declare the `CAMERA` runtime permission; opening a camera is a separate path. Camera resources may be busy or the device may have no flash, so show a disabled or absent control accordingly. [CameraManager](https://developer.android.com/reference/android/hardware/camera2/CameraManager) | **Direct, hardware-dependent.** |
| Flashlight beam shape | Apple offers width and length adjustment from its Island. Android `CameraManager` documents torch on/off and, for supported devices, strength level; those APIs do not establish a beam-shape actuator. | The Android target camera hardware and OEM APIs must be inspected before promising visual or functional beam-control parity. [Apple flashlight guide](https://support.apple.com/en-us/105001), [Android CameraManager](https://developer.android.com/reference/android/hardware/camera2/CameraManager) | **Unverified hardware capability; likely visual-only unless target exposes a documented control.** |
| Headset connection | Bluetooth profile connection broadcasts can report connected/disconnected headset state. | `BLUETOOTH_CONNECT` on modern targets; profile and OEM behavior require device testing. A connected headset does not prove it is the selected media route. Public evidence does not establish a universal left/right/case earbud battery contract. [BluetoothHeadset](https://developer.android.com/reference/android/bluetooth/BluetoothHeadset), [media route controller](https://developer.android.com/reference/android/media/MediaRouter2#getSystemController()) | **Direct for supported connection state; playback route and detailed battery conditional.** |
| Next scheduled alarm | `AlarmManager.getNextAlarmClock()` returns the next alarm posted through `setAlarmClock()` by any app. | This is not a running stopwatch/timer feed, and it does not grant snooze/stop controls. [AlarmManager](https://developer.android.com/reference/android/app/AlarmManager) | **Direct for next-alarm display only.** |
| AlarmKit-like countdown and alert | An app-owned Android alarm publisher can schedule a real `AlarmManager` alarm, keep its own countdown/paused/alerting state, and issue its own notification/actions. A named third-party alarm publisher may expose some phases through notifications. | `getNextAlarmClock()` supplies only the next alarm-clock time, not the firing state or actions. The native heads-up/full-screen alert is system-owned; an overlay must not claim to ring, snooze or bypass Focus merely by drawing. [Alarm scheduling](https://developer.android.com/develop/background-work/services/alarms), [time-sensitive notifications](https://developer.android.com/develop/ui/views/notifications/time-sensitive), [AlarmKit contract](../features/33-alarmkit-alarm-lifecycle.md) | **Direct app-owned lifecycle; publisher-dependent cross-app; system-owned alert.** Verify R10k. |
| Push to Talk channel | A cooperating Android publisher can report its own joined channel, speaker, transmit/receive phase and executable Talk action; another app may publish only a partial notification. | A call-state feed, media session, mic-use dot or generic notification does not prove channel membership or give authority to transmit. Real microphone capture has its own `RECORD_AUDIO` and foreground-service restrictions. [Android microphone service type](https://developer.android.com/develop/background-work/services/fgs/service-types), [PTT contract](../features/34-push-to-talk-channel.md) | **Direct for cooperating publisher; third-party contract-dependent; system surface target-specific.** Verify R10l. |
| Incoming/ongoing mobile call | `TelephonyCallback.CallStateListener` reports ringing/off-hook/idle for mobile calls. A publisher notification may supply a tap or action. | `READ_PHONE_STATE`; call-state callback does not supply full call identity or controls, and excludes many VoIP calls. Full telecom control requires the default-dialer `InCallService` role and its complete call UI contract. [Call-state callback](https://developer.android.com/reference/android/telephony/TelephonyCallback.CallStateListener), [InCallService](https://developer.android.com/reference/android/telecom/InCallService) | **Direct for mobile call state; publisher-dependent for exposed actions; role-dependent for full dialer parity.** |
| Third-party VoIP conversation | A cooperating calling publisher can register a real call with Core-Telecom, report direction, audio/video/hold capabilities and state, and post its own CallStyle notification. For another app, an enabled listener sees only its delivered notification fields/actions. | `MANAGE_OWN_CALLS` belongs to the calling publisher, not a replica seeking cross-app control. A generic CallStyle notification does not expose group membership, joining or a safe mute/merge command; retain native Telecom/call notification and confirm every action result. [Core-Telecom](https://developer.android.com/develop/connectivity/telecom/voip-app/telecom), [CallStyle](https://developer.android.com/develop/ui/compose/notifications/call-style), [communication contract](../features/45-live-communication.md) | **Direct for cooperating publisher; named-adapter partial across apps; SystemUI call surface owner separate.** Verify R10m. |
| Shazam recognition | Inspect the named Android Shazam package/version's actual active notification key, content, actions and destination through manual and Auto recognition, result/no-result and stop. | Apple documents a persistent Tap to Shazam notification and Auto Shazam modes, not a guaranteed listener-visible progress/result schema. A start affordance, microphone privacy indicator or media session alone does not establish a live recognition task or match. [Android Shazam settings](https://support.apple.com/en-gb/guide/shazam/devacc2a64ca/1.0/web/1.0), [recognition contract](../features/46-shazam-recognition.md) | **Publisher-dependent; direct only with an explicit cooperating recognition publisher.** Verify R10n and preserve native Shazam/privacy surfaces. |
| Live sports game monitoring | An app-owned publisher can track one user-chosen game ID and publish ongoing score/clock/phase updates with a real Unpin action; a listener can inspect a named sports app's posted ongoing notification and actions. | Android permits user-chosen sports monitoring as a Live Update, but promotion is system-decided and the publisher owns the game and Unpin result. A score alert, group summary or team-follow setting alone does not establish an active monitored game. Current Apple Sports Island presence must first be measured. [Android Live Updates](https://developer.android.com/develop/ui/views/notifications/live-update), [sports contract](../features/47-apple-sports-live-game.md) | **Direct app-owned; publisher-dependent across apps; native chip/shade system-owned.** Verify R10o. |
| MLB named game publisher | Inspect the installed MLB Android app's actual game-start/end, score-change, lead-change and pitching-change notifications, their keys, content, actions and lifetime; inspect an ongoing item only if actually posted. | MLB documents game alert categories but does not promise continuous listener-visible score/inning state or a promoted Live Update. Do not turn separate score alerts into a persistent MLB task, infer game identity from team text alone or merge the score source with MLB media playback. [MLB Android FAQ](https://www.mlb.com/es/dodgers/apps/mlb-app/faq-android), [MLB contract](../features/53-mlb-live-game.md) | **Named publisher-dependent; ongoing cross-app score feed unverified.** Verify R10u. |
| Wallet flight tracking | Inspect a selected Google Wallet build's delivered upcoming-flight and conditional flight-change notifications, plus their actual pass destination; use an explicit airline/tracker publisher only if it exposes ongoing flight state. | Google Wallet can update supported pass fields and post flight alerts, but these do not provide a universal continuous session to an ordinary listener. Distinguish Google Wallet, airline app and separate tracker identities; preserve native pass, shade and lock UI. [Google Wallet flight notifications](https://developers.google.com/wallet/tickets/boarding-passes/use-cases/trigger-push-notifications), [Wallet flight contract](../features/48-wallet-flight-activity.md) | **Notification observation publisher-dependent; ongoing flight state needs explicit publisher contract.** Verify R10p. |
| Wallet event ticket | Inspect a selected Google Wallet build's delivered upcoming-event and conditional pass-update notifications, with actual pass destination; use an issuer-owned task only if explicitly published. | A time/location pass reminder does not itself establish an ongoing event Live Update. An ordinary listener has no pass redemption authority or universal ticket-activity feed. Preserve native Wallet pass, shade and lock owners. [Google Wallet event notifications](https://developers.google.com/wallet/tickets/events/use-cases/trigger-push-notifications), [Wallet event contract](../features/49-wallet-event-ticket.md) | **Named notification observation; issuer-dependent ongoing activity; iOS Island presence must be measured.** Verify R10q. |
| Third-party timers, delivery, rideshare, sports, navigation | Listen to the publisher's ongoing notification and, where present, progress, text, `contentIntent`, and `Notification.Action.actionIntent`. Execute only non-null, current `PendingIntent`s; stale/canceled ones must fail safely. | User-enabled listener, per-app opt-in, publisher-specific semantics, potentially redacted content. A generic notification does not prove a timer's remaining seconds or a route's next turn. [Notification listener](https://developer.android.com/reference/android/service/notification/NotificationListenerService), [actions](https://developer.android.com/reference/android/app/Notification.Action), [PendingIntent](https://developer.android.com/reference/android/app/PendingIntent) | **Publisher-dependent.** Ship explicit adapters only for tested publisher/version combinations; use app-owned timer/navigation data if the app itself provides those features. |
| Scheduled and transient third-party activities | Observe a publisher's notification only when posted, and end its replica card when that notification or a stronger publisher contract says the session ended. An app-owned scheduled task can keep its own pending start time and start notification; an app-owned transient control can own its collapse/outside-tap/lock teardown. | A listener does not receive an ActivityKit-style `pending` or `transient` field from arbitrary Android apps. Do not invent a future activity before its publisher posts it or keep an ended transient card because an old notification remains. [Android notification listener](https://developer.android.com/reference/android/service/notification/NotificationListenerService), [Apple scheduling and transient styles](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities) | **Direct when app-owned; publisher-dependent or unavailable for another app.** Verify R22–R23 against an explicit publisher contract. |
| Remotely started or updated activity | An app-owned publisher can receive authenticated FCM data, reconcile it with its server/source state and post or update its own ongoing notification. A replica can then observe that posted notification through an enabled listener. | An ordinary listener cannot receive another app's private FCM payload or Apple's APNs activity token. Background FCM notification messages are routed to the system tray, while data messages can reach `onMessageReceived`; the callback has a short execution window and deleted messages require resync. Do not infer delivery latency or a successful end from a send timestamp alone. [FCM receiving guide](https://firebase.google.com/docs/cloud-messaging/android/receive-messages), [notification listener](https://developer.android.com/reference/android/service/notification/NotificationListenerService) | **Direct when app-owned; publisher-dependent across apps.** Verify R22a start, update, end, delay and resync against a real publisher. |
| User-invoked system control starts an activity | The publisher can expose a user-added Quick Settings `TileService`; its `onClick()` starts the publisher's own task and posts its real source notification. The replica then observes that notification or an explicit publisher integration. | A tile is a separate system control and cannot start an arbitrary other app's private task. The user must add it; a tile tap or source process wake does not itself prove that an Android Live Update chip was promoted or that the Island should display. [Android Quick Settings tile guide](https://developer.android.com/develop/ui/views/quicksettings-tiles), [Apple LiveActivityIntent](https://developer.apple.com/documentation/appintents/liveactivityintent) | **Direct when app-owned; publisher-dependent across apps.** Verify R22b invocation, start, duplicate and teardown. |
| App Shortcut starts an activity | An app-owned `ShortcutManager` shortcut can invoke the publisher's task path; the replica observes its explicit state or posted notification. | A launcher shortcut is not a portable hardware Action button and does not grant the replica another app's start command. Verify placement, actual invocation, task creation and listener arrival separately. [Android ShortcutManager](https://developer.android.com/reference/android/content/pm/ShortcutManager), [Action-button start](../features/29-action-button-start.md) | **Direct app-owned launcher route; hardware route selected-device-dependent.** Verify R22c. |
| Assigned Action-button control feedback | A selected OEM button mapping may invoke an app-owned command; the publisher can report its current control value and result. | `ShortcutManager` does not own a physical key, and a listener cannot infer its press or hold from a later notification update. A normal APK cannot promise another app's control symbol, value or keyguard result. [Android ShortcutManager](https://developer.android.com/reference/android/content/pm/ShortcutManager), [feedback contract](../features/32-action-button-control-feedback.md) | **Direct app-owned command; device-specific hardware mapping.** Verify R10j. |
| App-owned timers | Store a monotonic deadline and pause/resume/cancel state **per timer identity**; issue Android notifications appropriate to their actual lifecycles. | No dependency on another timer app. A third-party timer publisher may expose one summary notification rather than each deadline or control; do not infer sessions from it. [Android notification](https://developer.android.com/reference/android/app/Notification) | **Direct when app-owned; publisher-dependent for another timer app.** |
| Hotspot/tethering | On API 36+, `TetheringManager.registerTetheringEventCallback()` requires `ACCESS_NETWORK_STATE` and can report changes to tethered interfaces. | That callback does not establish a public client-count feed or guaranteed hotspot toggle; test actual selected-device state and start/stop access separately. [TetheringManager](https://developer.android.com/reference/android/net/TetheringManager), [callback](https://developer.android.com/reference/android/net/TetheringManager.TetheringEventCallback) | **Candidate direct status adapter; client count and control unverified.** |
| Other apps' camera/microphone use | `AppOpsManager.startWatchingActive()` only observes the caller's UID without `WATCH_APPOPS`. | A normal app cannot faithfully mirror global privacy dots from this contract. [AppOpsManager](https://developer.android.com/reference/android/app/AppOpsManager) | **Unavailable across apps; own-app activity only.** |
| Other apps' screen recording | `MediaProjectionManager` owns **this app's** consented capture session. Android 15's `WindowManager.addScreenRecordingCallback()` reports whether **this app's activities** are visible in a recording. | The callback does not provide another app's session, microphone mode or stop authority; the native projection chip is system-owned. A cooperating publisher may expose a specific notification/action. [Recording ownership](25-screen-recording-ownership.md) | **Direct for app-owned capture; own-activity visibility is a privacy signal; unavailable as a universal cross-app recording adapter.** |
| Satellite entry and connection guidance | On API 36+ with `FEATURE_TELEPHONY_SATELLITE`, `SatelliteManager.registerStateChangeListener()` can report whether the satellite modem is enabled. | This Boolean is not a connection-strength, pointing or task-session feed and does not open the OEM's pointing/emergency UI. Do not draw R27a dots/arrows or an R27 shortcut from modem state alone; inspect the chosen OS owner or a named publisher contract. [Satellite contract](../features/26-satellite-entry.md), [Android state callback](https://developer.android.com/reference/android/telephony/satellite/SatelliteStateChangeListener) | **Partial device signal; system/OEM-owned guidance and destination unverified.** |
| SharePlay-like group-session start | A named Android publisher may provide an explicit group-session event or an inspected invitation/task notification. `MediaSession` and call state cover playback and calling separately. | Neither a generic media session nor concurrent call proves that participants accepted a synchronized shared activity. Render only published session identity, phase and actions; leave native call/media/notification surfaces intact. [SharePlay start](../features/28-shareplay-start.md) | **Publisher-dependent; no universal call-plus-media inference.** |
| Voice recording by another app | A publisher's ongoing recording notification may expose state and actions; `AppOpsManager` cannot reveal other UIDs' microphone activity to a normal app. | A generic mic-use dot does not identify a recording session, elapsed time, pause action or destination. [AppOpsManager](https://developer.android.com/reference/android/app/AppOpsManager), [notification listener](https://developer.android.com/reference/android/service/notification/NotificationListenerService) | **Publisher-dependent; no universal Voice Memos equivalent.** |
| Nearby file transfer by another app | An app can track transfers it owns through Nearby Connections; a different app's transfer is visible only if it publishes a usable notification or another documented contract. | Do not equate an app-owned Nearby Connections transfer with visibility into Android Quick Share or any other app's private transfer. For an R13b comparison, inspect invitation, accept/decline, progress, failure, completion and background/internet continuation as separate states; show only phases actually published by the Android source. [Nearby Connections](https://developers.google.com/nearby/overview), [notification listener](https://developer.android.com/reference/android/service/notification/NotificationListenerService) | **Direct for app-owned transfer; publisher-dependent otherwise.** |
| Biometric unlock and other apps' authentication | Android keyguard and `BiometricPrompt` are system-owned; an app can request and receive results for its **own** authentication flow. | Another app's biometric session and result are not a general third-party event feed. Never claim a replica-drawn checkmark unlocked the device or authorized a payment. [Android BiometricPrompt](https://developer.android.com/reference/android/hardware/biometrics/BiometricPrompt) | **Direct for this app's own prompt; unavailable as universal cross-app Face ID/Apple Pay parity.** |

For notification adapters, apply the [listener visibility gate](27-notification-listener-visibility.md) before the [notification admission contract](20-notification-admission.md): a filtered or policy-blocked notification is unobserved, not proof that its task ended; listener visibility is discovery, not Island membership. Match package, notification identity, category/style, and supported action semantics; an app name or keyword alone is insufficient. On API 36+, record whether an ongoing notification actually has the system-set `FLAG_PROMOTED_ONGOING`; a publisher's promotion request is not proof of a visible chip. Maintain per-source timestamps and a bounded expiry so old notifications do not masquerade as current activities. Resnapshot after listener reconnection, deduplicate media notifications against the corresponding media session, and arbitrate simultaneous activities in one place. Keep a stable identity for **each activity**, even when several come from one package, and deduplicate only records known to describe the same session. Android notification ranking is not an ActivityKit `relevanceScore`; only an app-owned or explicitly cooperating publisher can supply equivalent session priority. A detected call or charging transition must not silently replace a user-selected activity without a documented priority rule and reference evidence. Since Apple's cross-app priority order is unpublished, initial Android priority is a **product policy to test**, not a claimed copy of iOS. [Android promoted flag](https://developer.android.com/reference/android/app/Notification#FLAG_PROMOTED_ONGOING), [Apple relevance score](https://developer.apple.com/documentation/activitykit/activitycontent/relevancescore).

When one publisher task cycles through several event payloads, retain its source identity and update only the current content/actions; do not allocate a new Island slot per event. An app-owned notification can update under the same `(tag, id)`, but third-party event identity and rapid-update delivery depend on what the publisher actually exposes. Follow the [one-activity rotation contract](../features/30-one-activity-rotating-content.md). [NotificationManager update](https://developer.android.com/reference/android/app/NotificationManager#notify(java.lang.String,int,android.app.Notification)).

Onboarding should request overlay access first, then notification access only when media or notification adapters are enabled. Request `READ_PHONE_STATE` or `BLUETOOTH_CONNECT` only when the user turns on those specific features. Provide a source-app allowlist, a clear pause/stop switch, and a local diagnostic screen showing each adapter's permission, last event, and reason for withholding a card. Avoid storing raw notification contents; keep only the fields needed for the active card. Reconcile state after process restart, rotation, user unlock, and permission changes. [Notification listener lifecycle](https://developer.android.com/reference/android/service/notification/NotificationListenerService), [overlay settings](https://developer.android.com/reference/android/provider/Settings).

For a third-party source, the [publisher adapter record](43-third-party-adapter-contract.md) specifies its tested package version, task identity, actual fields and action owner. Keep a notification key, media-session token and publisher task ID distinct until the source exposes proof that they describe one task.
