# Typography and icon fidelity

[Specification index](../../REFERENCE_SPEC.md) · [design contract](04-design-contract.md) · [comparison protocol](../verification/12-comparison-protocol.md)

The reference is what the **iPhone 18 Pro Max on the captured iOS 27 build actually renders**, not a package of fonts or icon files to copy into Android. Apple says its system font selection depends on platform, locale and text role; the San Francisco family has size-specific outlines and dynamic tracking. A third-party Live Activity can also supply its own content and styling, so do not label every observed glyph “SF Pro” by assumption. [Apple font overview](https://developer.apple.com/documentation/technologyoverviews/fonts), [Apple Fonts](https://developer.apple.com/fonts/).

## Asset provenance gate

Apple's currently published San Francisco download terms on its Fonts page restrict that download to Apple-platform UI mockups and state that the font may not be embedded in software. The download is therefore **not an Android font asset** under those terms. Apple's font overview likewise says not to bundle system-distributed fonts such as SF Pro. Inspect the license accompanying the exact font package before any use; this spec does not authorize copying, converting, subsetting or extracting Apple's font from an iPhone. [Apple Fonts license](https://developer.apple.com/fonts/), [Apple font overview](https://developer.apple.com/documentation/technologyoverviews/fonts).

Apple describes SF Symbols as integrated with San Francisco, with weights, scales, rendering modes, localization and animation layers. Its HIG also identifies some Apple-product symbols as copyrighted and noncustomizable. The public design page is a feature description, **not a cross-platform redistribution grant**. Before using an exported symbol or template in an Android build, review the exact SF Symbols download license and that symbol's restrictions. Until there is an applicable grant, use independently licensed Android or original assets and record their visual difference; do not silently include Apple's glyph outlines or exported vectors. [Apple SF Symbols](https://developer.apple.com/sf-symbols/), [SF Symbols HIG](https://developer.apple.com/design/human-interface-guidelines/sf-symbols).

For an Android candidate, record font and icon source, version, license, file/hash or system family, whether it is bundled or resolved from the target OS, and the exact range of glyphs it covers. Android supports system `Typeface` families, licensed font resources and provider-delivered fonts; the chosen font's weight, fallback and OpenType features must be verified on the selected phone rather than inferred from its family name. [Android Typeface](https://developer.android.com/reference/android/graphics/Typeface), [font resources](https://developer.android.com/develop/ui/views/text-and-emoji/fonts-in-xml), [Downloadable Fonts](https://developer.android.com/develop/ui/views/text-and-emoji/downloadable-fonts).

## Measure the reference and candidate

| Item | iPhone capture and source record | Android candidate and parity check |
| --- | --- | --- |
| Text role | Record source app/version, exact string, content region, locale/script, Dynamic Type size, bold-text setting, appearance and whether the text is first-party or fixture supplied. A fixture can log its SwiftUI font/text style; first-party font identity remains unverified unless Apple documents it. | Bind the same semantic string and locale. Record actual `Typeface`/fallback chosen on target, font file provenance, weight, variation settings, size and letter spacing. Compare rendered crop, not a declared font name. |
| Geometry | Measure cap/x-height where visible, ascent/descent, baseline, stroke width, counters, numeral width, inter-glyph spacing, line break/truncation and alignment to the pill and adjacent icon. Capture native pixels at short and long strings. | Measure the same values after device rasterization; tune layout and legal font settings without pretending metrics make different outlines identical. Keep a separate glyph-shape verdict. |
| Numbers and time | Capture timer/progress digits during several changes: `0`, `1`, `8`, colon, minute rollover and multi-digit width. Determine whether the actual reference uses proportional or tabular numerals in **that** field; Apple says default SF numerals are proportional and specific contexts can alter features. [Apple Fonts](https://developer.apple.com/fonts/). | If the licensed candidate supports it, test tabular-number features only where reference footage shows stable digit cells. Verify that digit changes do not shift the Island contour or neighboring symbols unexpectedly. |
| Symbol | Record the visible shape, dimensions, baseline/optical center, fill versus outline, stroke weight, tint/opacity layers, RTL/localized variant and animation frames. A fixture should log its declared SF Symbol name and configuration; do not infer a first-party symbol file from pixels alone. | Name the independently licensed or original Android asset, its path/version and permitted use. Compare contour, internal negative space, optical center, tint layers and any animated transition at target pixel density. |
| Text plus icon | Capture symbol-to-text gap and relative vertical alignment across compact, minimal and expanded regions, including larger text and RTL. | Compare combined composition and clipping under the same content; a close font with a mismatched icon baseline does not pass the content layer. |

Use the R1/R2/R4/R5 fixture variants, R6b element transitions, R8 landscape, R9/R10a media and timer content, and R15 accessibility/RTL as the minimum sample set. Include a short Latin label, long label, numbers, punctuation, an RTL label and at least one non-Latin script the chosen publisher supports. The [capture sheet](../reference/02-state-capture.md) stores each element's box and baseline; attach uncropped source frames and the Android render beside each asset decision. Apple SF Symbols can adapt to reading direction and script, so one left-to-right screenshot is insufficient for an icon set. [Apple SF Symbols](https://developer.apple.com/sf-symbols/).

## Verdict

Keep three decisions separate: **asset permission**, **visual glyph match**, and **functional content match**. A legally usable alternative can be functionally correct yet visually `approximate`. Matching one crop does not prove the font across dynamic text, locale, numeric updates or motion. Mark the content layer `matched` only after the [paired comparison protocol](../verification/12-comparison-protocol.md) passes the relevant strings, symbols and settings on the actual devices; if Apple assets cannot be licensed for the Android route and no alternative meets the frozen visual tolerance, record `approximate` rather than assigning an invented 1:1 score. The overall R-row stays `unverified` while other required layers or device captures are missing.
