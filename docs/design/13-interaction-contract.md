# Island interaction and gesture contract

[Specification index](../../REFERENCE_SPEC.md) · [capture matrix](../reference/02-state-capture.md) · [comparison protocol](../verification/12-comparison-protocol.md)

This is the interaction ledger for the iPhone 18 Pro Max/iOS 27 target. Apple's guide confirms touch and hold to expand, swipe up to collapse, tap to switch between two activities, and a cross-Island swipe to move among up to three. The [Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities) says tapping compact or minimal content opens its app. Apple's [Voice Memos guide](https://support.apple.com/guide/iphone/make-a-recording-iph4d2a39a3b/27/ios/27) also describes a tap that can expand or return to Voice Memos. These statements do not define a universal tap result for every source or the priority when gestures overlap. Resolve those details with native captures, not a single hard-coded gesture rule. [iOS 27 Island guide](https://support.apple.com/guide/iphone/view-live-activities-in-the-dynamic-island-iph28f50d10d/27/ios/27).

## Gesture arbitration to measure

For each relevant row, record touch-down coordinate, target activity ID, move path, hold duration, release/cancel coordinate, initial and final selection, and the app or system that received the event. Run taps near the contour edge and between detached items. Run slow and fast horizontal/vertical gestures and diagonal starts; record where the result changes. Repeat while a notification arrives, a media session ends, and the shade begins opening. Use the iPhone observations to set thresholds **before** tuning Android. Android's `ViewConfiguration` supplies device-scaled starting values, not evidence of Apple's thresholds. Android gestures can end with `ACTION_CANCEL`; the view must restore a stable state. [Android touch handling](https://developer.android.com/develop/ui/views/touch-and-input/gestures/viewgroup), [multitouch lifecycle](https://developer.android.com/develop/ui/views/touch-and-input/gestures/multi).

For an APK prototype, measure the window rectangle and actual touchable region in idle, compact, detached and expanded forms. `FLAG_NOT_TOUCH_MODAL` lets touches outside the window go to windows behind it. `FLAG_WATCH_OUTSIDE_TOUCH` can supply an initial outside-down location but cannot reconstruct an outside swipe or prove that a transient card should end. Check overlay suppression, Android 12+ untrusted-touch rules, shade pull, back navigation and ordinary app taps as separate outcomes. If the selected target cannot meet an iPhone interaction without taking over Android system gestures, mark that interaction `unsupported` for the APK route and evaluate the SystemUI route separately. [Android window flags](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_WATCH_OUTSIDE_TOUCH), [overlay touch rules](https://developer.android.com/about/versions/12/behavior-changes-all).

### Disconnected shapes and transparent gaps

R4/R5/R5b can show detached visible shapes with empty space between them. A single overlay window wide enough to contain all shapes may also cover those empty coordinates. `FLAG_NOT_TOUCH_MODAL` sends **outside-window** touches behind it; `FLAG_NOT_FOCUSABLE` implies that flag but does not make the inside of the window non-touchable. Transparent drawing or a child view declining a tap is not proof that the underlying app or shade received it. `FLAG_NOT_TOUCHABLE` applies to the **whole window** and would also disable its Island controls; Android 12+ further restricts pass-through touches beneath untrusted application overlays based on window visibility and combined obscuring opacity. Do not use a visual-only alpha value as proof of the input path: inspect the actual `WindowManager.LayoutParams.alpha`, window bounds and target event delivery. [Android window flags and touch security](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_NOT_TOUCHABLE), [Android 12 behavior](https://developer.android.com/about/versions/12/behavior-changes-all).

For an APK, try tightly bounded windows for independently interactive visible shapes, updating or removing their bounds as the layout morphs. This is a **candidate**, not a guarantee: multiple windows can be repositioned by the OS, may overlap during animation, and their combined obscuring opacity matters if any are non-touchable pass-through windows. Android's documented maximum obscuring opacity is `0.8`; query `InputManager.getMaximumObscuringOpacityForTouch()` on the target build instead of assuming it. For overlapping pass-through overlay windows, calculate the combined opacity as `1 - (1 - alpha1) * (1 - alpha2) * ...` using their window `LayoutParams.alpha` values; a visually clear pixel in an opaque window is not equivalent to a low-opacity window. Never rely on an undocumented touch-region hook to claim parity. For each R4/R5/R5b and the transition to/from R2, film and log a tap in each visible shape, every gap, the outer corners of the enclosing rectangle, and the first downward shade gesture. Log which window received `ACTION_DOWN`, whether the underlying app received its own down/up pair, whether SystemUI opened the shade, and whether `Untrusted touch due to occlusion` appears. Repeat on a third-party app, permission dialog, immersive app, rotated layout and with a native promoted chip. A visual match fails interaction parity if a gap steals or blocks the other app's tap. [Android window touch security](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_NOT_TOUCHABLE), [Android untrusted-touch diagnostics](https://developer.android.com/about/versions/12/behavior-changes-all), [Android overlay type](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#TYPE_APPLICATION_OVERLAY).

Record interaction parity as an outcome pair: **what the user saw** and **what the source/system actually did**. A matching animation with a missed tap, wrong destination, duplicate action, stolen shade gesture, inaccessible control or false success state does not pass. Use the five-layer verdict and frozen-tolerance process in the [comparison protocol](../verification/12-comparison-protocol.md).
