# Activity lifecycle and presentation state machine

[Specification index](../../REFERENCE_SPEC.md) · [capture matrix](../reference/02-state-capture.md) · [interaction contract](13-interaction-contract.md)

This is the **proposed Android implementation contract**, not a claim that Apple's private scheduler has been decoded. It keeps source truth separate from the Island's presentation. Every rule whose exact iOS behavior is unknown remains a native capture task. In particular, Apple's published `relevanceScore` ordering is [within one app](https://developer.apple.com/documentation/activitykit/activitycontent/relevancescore); it does not establish a total priority order among different apps, first-party system events, and user selection.

## State carried independently

| State | Required fields | Rule |
| --- | --- | --- |
| Source record | Stable activity/session ID, publisher and user/profile, adapter, last confirmed event time, current payload/actions, display lifecycle, independently confirmed task state, permission state | Keep separate records for simultaneous timers or activities from the same app. Merge a media notification with a media session only when they are proven to describe the same session. Package name alone is not identity. |
| Display lifecycle | `pending`, `active`, `stale`, `ended`, `dismissed`, `unavailable` | `pending`, `stale`, `ended` and `dismissed` are meaningful only if the publisher supplies their semantics. An ended activity may leave final Lock Screen content; a dismissed one has no visible card. Neither state alone proves its underlying task stopped. A permission loss or disconnected adapter makes unverified content unavailable until a fresh snapshot confirms it. [End/dismissal contract](../features/42-end-and-dismissal-policy.md) |
| Presentation | `idle`, `compact`, `multiple`, `expanded`, `alert`, `exiting`, plus a separate locked/StandBy surface | Rendering state never creates a source. `exiting` may animate a removed source but cannot keep its actions executable. Lock and StandBy have distinct content, privacy and input owners. |
| Selection | Selected source ID, visible source IDs, selection origin, ordering policy version | A visual slot is not an identity. Keep the user's target through compact/minimal/expanded changes unless native evidence establishes a replacement rule. |
| Conditional visibility override | Source ID, user gesture/owner, hidden time and observed restoration condition | Populate only if R5d confirms a hide operation on iOS 27. An override changes presentation, not source lifecycle, publisher notification or SystemUI chip state. |
| Input transaction | Pointer/focus target ID, gesture phase, pending action token, cancellation reason | Route an action to the current source ID and current executable capability. Aborted gestures and expired actions cannot report success. |

The renderer consumes one immutable snapshot of these fields per frame. Adapters report facts; the arbiter resolves a new snapshot; the renderer animates between snapshots. A notification, source callback or gesture cannot directly overwrite the drawing of another adapter.

## Events and transitions

| Event | State transition to implement or measure | Reference cases |
| --- | --- | --- |
| Source starts or becomes active | Add/update its record, then recompute visible slots and selection. Capture first visible frame and any start alert separately. A scheduled `pending` activity must not appear before the actual publisher contract allows it. | R1, R5a, R22 |
| Publisher app enters or leaves foreground | Keep its source record independent of presentation; apply only the **measured** foreground visibility policy, then recompute visible slots and selected source from current records. Do not cancel a task or native notification because its app is open. | R1a, R1b |
| Remote push starts, updates or ends an app-owned source | Accept only authenticated events for a stable source ID; reconcile delayed, duplicate and out-of-order revisions against publisher state before rendering. A confirmed end invalidates controls; a late update must not resurrect the same source. Distinguish transport receipt, source-state change, notification publication and first visible frame. A third-party listener sees only the publisher's exposed notification, not its private push stream. [Push ordering](../features/39-push-update-ordering.md) | R22a |
| Source content or relevance changes | Update only that ID, preserve unchanged content where the native transition does, and recompute visibility using the measured policy. A publisher cycling among events inside one Live Activity remains **one source**; replace its event payload and invalidate prior event-specific actions without consuming another Island slot. Do not convert an ordinary update into an alert. [Rotation contract](../features/30-one-activity-rotating-content.md) | R2a, R5a, R5c, R6a, R6b |
| User hides or restores a visible source, if confirmed | Change only its presentation override; retain the source record and continue processing real updates/end. Cancel any in-flight action whose visible hit target disappeared. Restore only on the measured trigger; do not infer that Android's native chip or shade card followed the replica. [Hide/restore contract](../features/37-activity-hide-restore.md) | R5d |
| App-owned alarm enters countdown, pause, alert or snooze | Keep one alarm ID through pre-alert countdown, pause/resume, system-owned firing alert, post-alert snooze and re-alert. Stop/cancel invalidates both countdown and alert controls; a future schedule without countdown need not occupy an Island slot. Do not infer these phases for another publisher from `getNextAlarmClock()` alone. [AlarmKit contract](../features/33-alarmkit-alarm-lifecycle.md) | R10k |
| Push to Talk channel joins, transmits, receives or leaves | Keep one confirmed channel ID while its speaker and transmit phase change. The actual publisher/system owns Talk and audio-session success; invalidate controls at leave, service loss or permission loss. An incoming mic dot is not a channel-state event. [PTT contract](../features/34-push-to-talk-channel.md) | R10l |
| Third-party VoIP conversation rings, joins, changes capability or leaves | Admit only after the publisher reports a real conversation/call source; an incoming push or app wake alone is not a ring state. Keep the reported ID while its phase, participants, active media members, audio/video and hold support change. Show only confirmed controls; wait for publisher/Telecom result before claiming answer, hold, merge or end. A call notification or mic dot alone does not reveal the private phase. [Communication contract](../features/45-live-communication.md) | R10m |
| Satellite connection guidance changes | Only a verified native SystemUI/OEM or cooperating-publisher source can change connection-strength dots or turn arrows. Preserve that session's identity through signal and pointing updates; remove guidance when its owner confirms loss/end. The public modem-enabled callback cannot create or update a guidance session. Keep the Connection Assistant destination bound to its current owner. [Satellite contract](../features/26-satellite-entry.md) | R27, R27a |
| Alert arrives | Temporarily enter `alert` for its real source and record wake/sound/return behavior; determine whether it changes selection from native footage. Alert completion restores a fresh snapshot, not a cached source list. | R6, R22 |
| Source becomes stale | Keep its identity and whatever content is actually published; apply an expiry only if the source contract calls for it. Record whether iOS keeps, changes or removes its Island slot. | R12 |
| Publisher task ends or a notification record is removed | A confirmed task end changes that task's lifecycle. A notification-removal callback first invalidates that notification's controls/content and withdraws a card supported only by it; its reason does not by itself prove task end. Keep a separately confirmed media/publisher task current under its own record. Optionally render a measured exit, then promote another confirmed active source. If the selected source disappears during a gesture, cancel and re-resolve. Track final Lock Screen content and dismissal separately. [Android removal reasons](https://developer.android.com/reference/android/service/notification/NotificationListenerService#onNotificationRemoved(android.service.notification.StatusBarNotification,android.service.notification.NotificationListenerService.RankingMap,int)) | R7, R10f, R12a, R12c; Android listener trials |
| Listener disconnects, access is revoked or profile changes | Mark affected records unavailable and stop exposing their data/actions. Reconnect by taking a fresh authorized snapshot and matching stable identities where possible; do not replay cached content as live. | R15 and Android permission/restart tests |
| Basic Live Activity or frequent-update setting changes | Treat basic publisher authorization and push frequency as distinct inputs; capture whether an existing source remains independently from whether a new start or subsequent update is allowed. The Android renderer follows observed publisher state and its own listener/overlay access, not an inferred iOS setting. | R15a |
| User-invoked intent starts a source | Receive a confirmed new publisher record after the control action; distinguish intent invocation, source creation, notification publication and first frame. A duplicate tap must not fabricate duplicate source IDs. | R22b |
| User taps, holds, swipes or cancels | Resolve hit target at touch-down; apply source-specific action/selection only after the measured gesture commits. For a toggle, track requested versus committed value and a unique invocation ID; abort or rollback on cancellation, failure or source loss. Expose the real result to accessibility. | R2–R5, R18/R18a, R19, R24 |
| App-owned or first-party transient starts | Enter its measured initial expanded state; independently handle collapse, outside tap, app departure and lock as teardown triggers. An arbitrary notification does not imply transient semantics. | R9a, R23 |
| Media route transfer requested | Hold a pending action for the selected media session; show success only after the route owner confirms transfer, and clear pending state on failure, timeout, source loss or permission loss. | R9a, R20 |
| Lock, unlock or StandBy begins | Hand rendering and actions to the applicable system surface; apply native privacy/redaction before display. On unlock, rebuild the Island from current sources and selection evidence. | R11, R11a, R12b |
| Android native chip is promoted, demoted or dismissed | Observe the system's actual chip state and reconcile ownership of the same publisher's tap/controls; never create two competing affordances for one session. Promotion requested by a publisher alone is insufficient. | Android API 36+ proof gate |

## Visibility and arbitration boundaries

- The [iOS 27 guide](https://support.apple.com/guide/iphone/view-live-activities-in-the-dynamic-island-iph28f50d10d/27/ios/27) documents navigation among up to three visible activities. Capture R4, R5, R5a and R5b to establish which sources occupy those slots, **which publisher view is used in each visible position**, how selection changes, and what happens when a fourth source is accepted. The older [Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities) describes two minimal activities, so it cannot specify the third slot's content mode. A fourth source may remain active in the source store without being rendered; never silently draw more than the measured capacity.
- Apply Apple's documented within-app relevance and earliest-start tie behavior only where it actually applies. Cross-app order, first-party system transient priority, alerts, and user-selection persistence are **unknown for the target build**. Store a versioned Android prototype policy and its inputs in diagnostics; label it `approximate` until paired capture validates its outcomes. Android notification ranking is not an ActivityKit relevance score.
- `idle` requires zero visible eligible sources, not necessarily zero stored records. `compact` presents one selected source. `multiple` presents the measured two- or three-activity composition. `expanded` belongs to a specific live source, not to a package. `alert` has a timed return target that must be recomputed if sources change. `exiting` has no executable actions.
- Keep source truth and surface truth distinct. A Lock Screen dismissal does not prove the underlying task ended. A media session may continue while its route offer disappears. An Android Live Update chip can disappear while its notification or source remains active. [ActivityKit lifecycle](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities), [Android notification listener](https://developer.android.com/reference/android/service/notification/NotificationListenerService).
- A user-hidden Island presentation, if R5d exists on the target build, is another surface-only change. Do not conflate it with publisher stop, Lock Screen dismissal, foreground suppression, overflow or Android Live Update demotion. The exact restore trigger and selection after restoration require native evidence. [Hide/restore contract](../features/37-activity-hide-restore.md).

## Race cases to verify

1. Start A, B and C; select B; end B during a horizontal swipe. Confirm cancellation, successor, slot order and action target, then let A and C end. This proves `0 → 1 → 2 → 3 → 2 → 1 → 0` without a stale slot.
2. Start two activities from one publisher with unequal scores, update their scores, then start one from another publisher. Verify the published within-app rule separately from the still-unknown cross-app order (R5a).
3. Start a fourth accepted source while three are visible; update and end both a visible and a hidden source in separate runs. Confirm the stored source count, visible cap, any hidden-source navigation and the promoted successor without reusing a departed source's action target (R5b).
4. Begin an expanded action or toggle, remove its notification or media session before the callback, and deliver a late success/failure response. The ended source cannot be revived by that response, and an optimistic toggle must not leave a false committed value (R18/R18a, R9a).
5. Revoke notification access while two publisher cards are visible, reconnect, then resnapshot. No cached private text or control may survive the gap as an active card.
6. Start an alert during a manual hold or swipe, then lock before its return animation. Record whether iOS cancels, interrupts or restores selection; Android must not route the abandoned gesture to the wrong source (R6, R11).
7. Trigger a transient Music route offer, transfer successfully or fail, then separately collapse, tap outside, leave the app and lock. Confirm each teardown and the remaining media session independently (R9a, R23).
8. Promote a publisher's Android Live Update to a system chip, then demote, dismiss and end it. Trace which surface owns tap, shade and accessibility actions at each point.
9. Keep one source ID while its publisher cycles through three event IDs; change destination/action between events, then overlap a second source and reconnect the listener. Confirm that source count stays stable, former event actions expire and selection does not jump as though a new activity started (R5c).
10. Pause an app-owned alarm near its deadline, resume into the alert, snooze into a second countdown and stop it while another Island source is visible. Confirm that the real system alert is heard/seen, each action applies to the same alarm ID, and no stale countdown or duplicate chip remains (R10k).
11. Remove a notification by click, snooze and lockdown while its independently confirmed media/publisher task continues; compare an app cancel followed by a new post. The old notification's private fields and actions disappear immediately, and a fresh post cannot inherit an expired action token. Record the Android removal reason, source IDs, native chip/shade and whether the independent task remained live.

For every sequence, log source IDs, event ordering, policy version, input owner, visible IDs, selected ID, presentation state and action result. Compare the Android trace with timestamped native footage through the [comparison protocol](../verification/12-comparison-protocol.md). The proposed state machine is complete as an **implementation contract** when every transition above has an observable test path; it is 1:1 only when those paths match the selected iPhone and Android builds.
